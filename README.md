# NasoTwin — Model 2

**A Multiscale PK–PD Simulation Framework for Engineered Nasal Microbes**

Code for the [SUSTech-MED NasoTwin Wiki](https://2026.igem.wiki/sustech-med/model-nasotwin#overview).

NasoTwin connects nasal bacterial delivery, metabolic exchange and sustained
drug supply in a four-module computational framework. The models translate
spray settings and bacterial activity into local retention, metabolite dynamics,
drug exposure and resource allocation.

NAC and SFN come from the SynBioPilot autonomous discovery and automatic
screening workflow. ChassisGate automatically classifies both as D1. NasoTwin
uses these candidate identities in its delivery, response and allocation models;
[SynBioPilot](https://github.com/Xiang-Chen1207/SynBioPilot/blob/main/docs/result-provenance.md)
describes the discovery workflow and associated records.

This repository contains Python source code, model configurations and runtime
dependencies. Experimental inputs and generated outputs are managed separately.

## Modules

| Wiki chapter | Model IDs | Computational methods | Code guide |
|---|---|---|---|
| [Nasal Deposition & Bacterial Dynamics](https://2026.igem.wiki/sustech-med/model-nasotwin#nasal-deposition-bacterial-dynamics) | M1–M2 | Particle tracking, finite-volume transport, attachment and four strain-level growth fits | [Nasal module](modules/nasal/README.md) |
| [Metabolic Exchange](https://2026.igem.wiki/sustech-med/model-nasotwin#metabolic-exchange) | M3–M4 | Endpoint calibration, nitrogen-balance dynamics and 656-point design search | [Metabolic module](modules/metabolic_exchange/README.md) |
| [Drug Delivery & Response](https://2026.igem.wiki/sustech-med/model-nasotwin#drug-delivery-response) | M5–M7 | Endpoint analysis, compartmental PK–PD and production inversion | [Drug module](modules/drug_delivery/README.md) |
| [Integrated Optimization](https://2026.igem.wiki/sustech-med/model-nasotwin#integrated-optimization) | M8 | Four-strain allocation under seven constraints, grid baseline and genetic search | [Optimization module](modules/integrated_optimization/README.md) |

The integrated design allocates Lp-Q, Lp-NH3, Lp-NAC and Lp-SFN to minimize
total emitted CFU. Three first-hour metabolic criteria regulate Gln removal
and ammonia; four NAC/SFN response channels are evaluated at 24 h.

## Installation

Use Python 3.11. From the repository root:

```bash
mkdir -p .runtime/tmp .runtime/cache
export TMPDIR="$PWD/.runtime/tmp"
export XDG_CACHE_HOME="$PWD/.runtime/cache"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --no-cache-dir -r requirements.txt
```

The core workflows use NumPy, SciPy, pandas and Matplotlib. Install the nasal
transport and geometry dependencies for the first module:

```bash
python -m pip install --no-cache-dir -r requirements-nasal.txt
```

## Inputs

Supply the inputs for the workflow you want to run. Each module README gives
the expected file locations and available path options.

| Workflow | Input files |
|---|---|
| Metabolic and drug analysis | Processed assay tables in `data/experimental/湿实验结果总表.md` |
| Nasal spray simulation | NC04 surface mesh in STL format |
| Nasal growth and coupling | One 47-point OD600 trajectory per strain in an Excel workbook, plus spray trajectories |
| Integrated optimization | Coupling NPZ, metabolic calibration JSON and PK–PD calibration JSON generated by the preceding workflows |
| Figure generation | Tables and trajectories produced by the corresponding models |

JSON configuration files specify model parameters, numerical settings and
search ranges. Metabolic `source_table` paths are resolved relative to their
configuration file. `modules/integrated_optimization/config.json` selects
upstream results through its `inputs` settings, with paths relative to that
module. The default inputs are generated by the workflow below.

## Running the models

After preparing the assay table, growth workbook and spray trajectories, run
workflows from the repository root in this order:

```bash
# Four strain-level growth fits and first-hour retention kernels
python -B run.py nasal-growth --workbook /path/to/growth.xlsx
python -B run.py nasal-coupling

# Metabolic endpoint fitting, dynamics and design-space search
python -B run.py metabolism

# Drug endpoint analysis and continuous-supply PK–PD
python -B run.py drug-endpoints
python -B run.py drug-pkpd

# Integrated baseline followed by genetic search
python -B run.py optimize
python -B run.py ga
```

The nasal coupling command accepts `--trajectory-dir` for the three selected
spray-seed archives. Its default fit input is the file generated by
`nasal-growth`. The optimizer consumes the following current-run outputs:

| Upstream workflow | Input to integrated optimization |
|---|---|
| `nasal-coupling` | `modules/nasal/outputs/coupling/coupled_results.npz` |
| `metabolism` | `modules/metabolic_exchange/results/integrated_parameters.json` |
| `drug-pkpd` | `modules/drug_delivery/pkpd_continuous_results/conditional_pkpd_results.json` |

Run `optimize` and then `ga` after updating these upstream results. The
retention loader uses one growth trajectory per strain, averages the spray
seeds, and normalizes by the emitted dose stored in the coupling output.

For a spray scan with an external geometry file:

```bash
python -B run.py nasal-scan --geometry /path/to/NC04.stl \
  --workers 4 --coarse-only --output-dir modules/nasal/outputs/spray_scan
python -B run.py nasal-grid-figure
python -B run.py nasal-coupling \
  --trajectory-dir modules/nasal/outputs/spray_scan/trajectories
```

For the growth and coupling figures:

```bash
export NASOTWIN_GROWTH_WORKBOOK=/path/to/growth.xlsx
python -B run.py nasal-growth-figures
python -B run.py nasal-plots --data-dir modules/nasal/outputs/coupling
```

Additional figure workflows:

```bash
python -B run.py drug-figures
python -B run.py optimization-figures
```

## Wiki figures and tables

| Wiki outputs | Workflow |
|---|---|
| N2d: deposition grid | `nasal-grid-figure` after `nasal-scan` |
| N2e and growth metrics | `nasal-growth-figures` |
| N2f: coupled bacterial dynamics | `nasal-plots` after `nasal-coupling` |
| ME1–ME6: metabolic endpoints, dynamics and design space | `metabolism` |
| N4a, N4b, N4d: transport, calibration and production design | `drug-figures` after `drug-endpoints` and `drug-pkpd` |
| N4c: continuous-supply exposure and response | `drug-pkpd` |
| N5a–N5c and Tables N5-1/N5-2 | `optimize`, then `ga`; `optimization-figures` redraws figures |

Module READMEs map the Wiki equations and figure panels to the implementation
functions and generated filenames. The N5b response panels use E02
(NAC–RAW TNF-α) and E03 (SFN–RAW IL-6), matching the Wiki comparison.

`run.py` forwards additional arguments to the selected script and resolves
relative command-line paths from the repository root. Use `python -B run.py
--help` to list workflows. Module-specific scripts are also executable directly.

Each module writes tables and figures to its own output directories. Runtime
files and caches stay within the repository. The metabolic runner accepts
`--check` to check endpoint recovery, nonnegative concentrations, nitrogen
balance and the zero-exposure limit using the supplied assay table.
